# Persyst V10 MMX — Authoritative Reference

**Source-of-truth file:** `Ref Files/PedQuEST_Pennsieve_V10_research.mmx` (committed copy; authored from `C:\ProgramData\Persyst\PedQuEST_Pennsieve_V10_research.mmx`)

**MMX root description:** `PedQuEST Trends V10`

**Generated:** from a direct XML parse of the shipped MMX. It is the only template this pipeline supports; earlier templates are archived under `_archive/` and are not readable by this release.

**Inventory:** 22 panels · 10 engines · 370 unique instrument definitions · 962 panel-slot references.

This document is the single source of truth for which **engine** produced each **trend column** in each **CSV panel export**. The companion JSON catalog at `docs/persyst_v10_catalog.json` is the machine-readable form, regenerated by `scripts/sync_persyst_docs.py`. **Exact per-family unit / engine / export-group / value-range values are not restated here — they live in the code-generated `docs/persyst_families.generated.md` (the cross-artifact contract); see the "Anti-drift" note in `INDEX.md`.**

> **What this template defines**
> - **Non-lateralized `Anterior` / `Posterior` channel sets** — whole-head regional aggregates for FFT power, power ratios, aEEG, BSR, PeakEnvelope, and SEF. These are **not** asymmetry pairs; the `Asym *` channels are used only by the REASI indices. Slugs: `fft_{band}_anterior`, `aeeg_anterior_*`, `suppression_anterior`, `sef_95_anterior`, `peak_envelope_anterior`, etc.
> - **Relative band power** — `FFT PowerRatio, {band}/1-30 Hz` (band ÷ 1-30 Hz broadband total) for delta/theta/alpha/beta over 9 regions → family `relative_power`, slug `rel_{band}_{location}`.
> - **ADR / TDR are distinct** — `8-13/1-4` (ADR) and `4-8/1-4` (TDR) resolve to separate `adr_*` / `tdr_*` slugs. The mapper classifies ratios by denominator: `//1-4` → ADR/TDR, `//1-20` → RAV, `//1-30` → relative power.
> - **Status Epilepticus & Seizure Burden (Persyst-native)** — 6 ESE metrics (ACNS / Advanced / Combined × Binary / Percent) + 2 Seizure Burden metrics (Percentage / Category, 5-min window). Slugged `status_epilepticus_persyst_{method}_{output}` and `seizure_burden_persyst_{output}` — **kept distinct from the pipeline-calculated** `status_epilepticus_screen_flag` / `seizure_burden_pct`, which are NOT replaced.
> - **TimeAvg windows are 64 s and 120 s only** — 52 instruments, no 30-minute layer. See Section 5.
> - EKG / Heart Rate present (10 engines incl. the two `Heart Rate Engine` instantiations; `EKG Channel` + `Heart Rate` + `Heart Rate01`).
>
> **Persyst-native precedence (pipeline decision):** where Persyst emits a native Anterior/Posterior or relative-power value AND the pipeline would otherwise compute a same-named feature (bilateral `fft_{band}_anterior`, band-sum `rel_{band}_{region}`), the **native value wins** — `compute_regional_features` / `compute_all_derived` skip any column already present. **Exception — Status Epilepticus & Seizure Burden:** the Persyst-native ESE/burden trends are kept *alongside* the calculated screen flag / burden percentage (distinct `_persyst` slugs); neither replaces the other.

> **Spectrogram bin slug convention:** `<family>_<channel-group>_<center-freq>hz` where `<center-freq>` is the 2-decimal **center** frequency in Hz with the decimal point written as an underscore, so the whole slug is a valid identifier — e.g. `fft_spec_left_hemisphere_0_50hz`, `rhythmicity_left_anterior_9_00hz`. Read the frequency out of the slug; never off the bin index.

> **FFT power scale — how the unit is determined (resolved 2026-06-11).** Persyst's FFT power scale is **user-configurable** (Help, *Trend Types: Frequency*: "power parameter can be expressed as **µV², µV, dB, or sqrt(µV)**"), encoded per-instrument in the MMX as the **`PowerType`** attribute. In this template: `FFT_Power`, `FFT_PowerRatio`, `FFT_Edge`, `Rhythmicity`, `Asymmetry` use **`PowerType=1`**; `FFT_Spectrogram` uses **`PowerType=3`**; `Coherence` uses `PowerType=0`. The exported value's unit follows the configured scale — **not** a Persyst-universal default (the shipped `P15.mmx` example uses different scales).
>
> - **FFT band power (`PowerType=1`) = µV² (power).** Confirmed empirically against `subject-1_research-short.csv`: the delta-band power column equals the integral of the squared spectrogram, `Σ(spec_bin²)·Δf` (median 9.6 vs 13.1 µV², ratio 0.73, corr 0.983 — the offset is band-edge/smoothing), **not** its square root (which would be µV amplitude, ~2.6× too small). Matches `PersystTrendCSV_Format_Reference.md` §3.5.
> - **FFT spectrogram (`PowerType=3`) = µV/√Hz (amplitude spectral density).** Persyst's display label "sqrt(µV)/Hz" (Help) is loose notation for **√(µV²/Hz) = µV/√Hz**; `PersystTrendCSV_Format_Reference.md` §3.12 states it precisely and instructs "**square each value** to recover power spectral density in µV²/Hz". So `sqrt(µV)/Hz` (help) and `µV/√Hz` (our unit) are the **same quantity**.
>
> Caveat: these hold for the **PedQuEST MMX's `PowerType` settings**. A different MMX with a different `PowerType` would change the unit — always read `PowerType` from the engine, don't assume.

## 3b. Status Epilepticus & Seizure Burden (Persyst-native metrics)

> **Sources.** Seizure Burden definition is from the Persyst-controlled *Quick Reference Guide for a Reduced Set of Electrodes and the Provided Seizure Burden Trend* (Persyst document **6243-02**, 2025-06-06) and the Persyst 15 Help *Trend Panel: Seizure Burden*. The ACNS thresholds below are the **ACNS 2021 Standardized Critical Care EEG Terminology** definition (the basis Persyst labels its "ACNS Metric"); the Persyst "Advanced" and "Combined" methods are proprietary and not publicly specified. ACNS criteria confirmed via OpenEvidence (Hirsch & Gopaul, *Clin Neurophysiol* 2025; Sheikh et al., *Neurology* 2025).
>
> ⚠️ **Pediatric caveat (critical for PedQuEST/POCCA):** Persyst seizure detection — and therefore Seizure Burden and the ESE metrics derived from it — is **validated only for adults ≥18 years** (QRG 6243-02: "Persyst 15 seizure detection has not been tested with patients under 18 years old"). For pediatric cohorts these trends are **research-use, unvalidated**; verify against expert markings and pre-specify their role in the SAP. They are ingested **in addition to** — never replacing — the pipeline-calculated `status_epilepticus_screen_flag` / `seizure_burden_pct`.

### Seizure Burden (ClsId `{91D5E170-E2B1-44A6-B062-7B8CA255DF82}`)

Computed on the **previous 5-minute period, every 10 s**; engine epoch/step = 10 s; `AssessmentPeriod=300` s. Results display 400 s after the period ends (or at end of record). Derived from the Persyst seizure-**probability** output to match expert markings of seizure prevalence over the 5-min epoch — **not** an arithmetic sum of discrete seizure-detection durations. Two output variants (`OutputSB`):

| Variant (`OutputSB`) | Slug | Scale |
|---|---|---|
| Percentage (`0`) | `seizure_burden_persyst_percentage` | % of the 5-min epoch with seizure activity (0–100) |
| Category (`1`) | `seizure_burden_persyst_category` | 0–3 ordinal (below) |

Category scale (QRG 6243-02 / Help):

| Code | Seizure seconds in 5-min epoch | Label |
|---:|---|---|
| 0 | none, or < 30 s | (no/minimal) |
| 1 | ≥ 30 and < 150 s | **Frequent** |
| 2 | ≥ 150 and ≤ 270 s | **Abundant** |
| 3 | ≥ 270 s | **Continuous** |

Per-category event sensitivity (QRG, adult ICU/EMU validation): cat 1 ≈ 89.7 % (95% CI 83.9–93.1), cat 2 ≈ 73.2 % (58.9–82.1), cat 3 ≈ 94.7 % (73.7–100). Uncertainty rises with category — the QRG explicitly cautions the cat-2/cat-3 lower CI bounds are well below cat-1.

### Status Epilepticus (ClsId `{A90DC6F5-A8DB-4712-8805-3CCB9203BB15}`)

Electrographic status epilepticus screen, engine epoch/step = 10 s. Six variants = 3 methods (`MethodESE`) × 2 outputs (`OutputESE`):

| `MethodESE` | Method | `OutputESE` | Output | Slug |
|---:|---|---:|---|---|
| 0 | ACNS | 1 | Binary | `status_epilepticus_persyst_acns_binary` |
| 1 | Advanced | 1 | Binary | `status_epilepticus_persyst_advanced_binary` |
| 2 | Combined | 1 | Binary | `status_epilepticus_persyst_combined_binary` |
| 0 | ACNS | 0 | Percent | `status_epilepticus_persyst_acns_percent` |
| 1 | Advanced | 0 | Percent | `status_epilepticus_persyst_advanced_percent` |
| 2 | Combined | 0 | Percent | `status_epilepticus_persyst_combined_percent` |

- **Binary** = 0/1 (ESE criteria met in the assessment window); **Percent** = fraction of the window classified as ESE-state (0–100).
- **ACNS method** implements the **ACNS 2021** ESE definition: an electrographic seizure lasting **≥ 10 continuous minutes**, OR total seizure duration **≥ 20 % of any 60-minute epoch** (≈ ≥ 12 min/hr). The underlying electrographic-seizure criterion is > 2.5 Hz for ≥ 10 s, or definite evolution ≥ 10 s.
- **Advanced** / **Combined** are Persyst-proprietary methods (thresholds not publicly documented); treat as vendor-specific until Persyst IFU specifics are obtained.

### Relationship to the pipeline-calculated screen

The pipeline's `status_epilepticus_screen_flag` (in `qeeg/analysis/seizure.py`) is a **separate** algorithmic screen: ≥ 30 min continuous OR ≥ 50 % of any 1-hour window OR repeated close onsets, derived from the Persyst seizure-detection trend. It uses **different thresholds** from the ACNS metric (≥ 30 min/≥ 50 % vs ≥ 10 min/≥ 20 %) and must not be conflated with `status_epilepticus_persyst_*`. Both are exported; pre-specify the primary endpoint per study.

## 5. TimeAvg windows (Research-TimeAverages panel)

The `Time Avg <0,N> [source]` instruments wrap an upstream trend in a running-mean window of `N` seconds. This template uses **two** window sizes, 52 instruments in total:

| Window | Count | Use | Notes |
|---|---:|---|---|
| 64 s | 16 | Short-window smoothing | FFT_Power quadrant bands (1-4 / 4-8 / 8-13 / 13-20) |
| 120 s (2 min) | 36 | Standard clinical smoothing — ADR, RAV, band power | FFT_Power hemisphere/All bands, FFT_PowerRatio 8-13//1-20 and 6-14//1-20 across regions and single chains |

**There is no 30-minute (1800 s) layer.** Any audit script or analysis expecting one is reading a stale expectation, not this template.

Read the window from the **MMX instrument name**, never the CSV display label: Persyst does not rewrite a display label when the underlying window changes, so the label can name a window the instrument no longer uses. The slug carries the resolved window (`_avg64s`, `_avg2m`), and an averaged column is a smoothed view of a raw trend — never an independent variable alongside its own source.

## 6. Statistical implications (preliminary)

Before re-running statistical analyses, propagate the following into `STATISTICAL_METHODS_AND_AUDIT.md` and `DATA_DICTIONARY_v4.md`:

1. **FFT independence rule unchanged.** FFTEngine01 epoch=4 s, step=8 s. `n_effective_fft` and `n_effective_basis = *_cadence_adjusted` for all FFT-family features remain correct.
2. **Beta 13–30 Hz is derived, not Persyst.** Any `fft_beta_wide_*` column must be documented as a pipeline-derived sum of 13–20 + 20–30 binned FFT spectrogram values, not as a Persyst FFT_Power instrument. Decide whether to keep, rename to `fft_beta_derived_*`, or drop.
3. **Averaged columns are not independent variables.** The 52 TimeAvg instruments are 64 s and 120 s smoothed views of raw trends (Section 5). The slug carries the window, so an average and its own source must never be pooled or entered into one model as separate predictors.
7. **Status Epilepticus & Seizure Burden are dual-sourced.** The export carries Persyst-native ESE/burden metrics (`status_epilepticus_persyst_*`, `seizure_burden_persyst_*`) **in addition to** the pipeline-calculated `status_epilepticus_screen_flag` / `seizure_burden_pct`. They use different methods (Persyst ACNS/Advanced/Combined vs the pipeline's ≥30-min-OR-≥50%-hourly screen) and must not be conflated; pre-specify which is primary in the SAP.
4. **Per-channel rhythmicity (new).** If publications need single-channel rhythmicity, ingestion code must add ingestion for `Rhythmicity Spectrogram 3.00 <chan>_avg` where `<chan>` is one of the 18 BP-Long bipolar pairs — these are present in the `Rhythmicity by Channel` panel and the `Research` panel, but not yet in `column_mapper.FEATURE_FAMILIES`.
5. **Sleep stage code.** `SleepStages` ClsId `{E2FF9712-5313-4818-8F11-4B8E4164753B}` is present and exported as a single column with codes 0–5 (see Section 3.23 of `PersystTrendCSV_Format_Reference.md`). If sleep-stage stratification matters for an analysis, add it to the data dictionary.
6. **EventDensity for spikes is a separate type from SpikeDensityV1.** EventDensity is a count-per-epoch detector, SpikeDensityV1 is a rate (spikes/min). The pipeline already maps both, but the data dictionary should make the distinction explicit so reviewers do not double-count.

## 7. Sub-column contract (cross-reference)

For the authoritative per-sub-column semantics (FFT bin frequencies, aEEG percentile order, Coherence bin formula, Rhythmicity sqrt scaling, Electrode Signal Quality count, etc.), see the companion document:

**[`PersystTrendCSV_Format_Reference.md`](../Ref%20Files/PersystTrendCSV_Format_Reference.md)** — vendored under `Ref Files/`.

The CSV Format Reference's Section 3 (Trend Types) defines, for every instrument family:
- the expected number of sub-columns;
- what each sub-column represents (frequency bin, percentile, channel, etc.);
- the units and value range.

Those are the contracts the pipeline must honor on CSV import. The qEEG ingestion code validates them via `qeeg/ingestion/subcol_validator.py` (see Section 9), which is built directly against the CSV Format Reference's Section 3 tables — so when the reference is updated for a new MMX version, the validator's expected counts must be updated to match.

## 8. Verification pattern for future MMX/CSV pairs

Whenever a new MMX is uploaded, the qEEG pipeline must:

1. Parse the MMX panels and resolve every Instrument to its `ClsId` / family (via `qeeg.ingestion.mmx_parser.parse_mmx`).
2. On the first CSV export, for each `I{n}` instrument observed in the trend-name row:
   - Look up its family from the trend name.
   - Compare the observed `max(sub-col index)` against the expected count in the CSV Format Reference Section 3.
   - **Hard-fail** on mismatch for fixed-cardinality families (3, 5, 18, 40, 63, 97, 16, 2, 1).
   - **Warn-and-log** on mismatch for recording-system-dependent families (`ElectrodeSignalQuality` — depends on acquisition channel count; any future spectrogram whose bin count is driven by `WaveformRate`/`PtsPerWindow`).
3. Persist the observed pattern in `data_dictionary.json` so reviewers can re-verify post-hoc.

This validator is implemented at `qeeg/ingestion/subcol_validator.py`. Its expected-count table is the **single Python source** that mirrors `PersystTrendCSV_Format_Reference.md` §3 — keep them in sync.
